# Changelog

What changed for a user or an operator, newest first. One line each — the *how* is in the commit, the *why* is in [decisions/](decisions/README.md), the *current behaviour* is in [features/](features/README.md). `/ship` adds a line here for each change.

## Unreleased (branch `feat/mobile-web-parity`, not yet pushed)

- **Attendance and salaries:** a malformed or empty request to save attendance or set shifts per day now answers 400 instead of 500; shifts per day must be a real number 1–3 (the text "2" and `true` used to be accepted, `true` as 1); the month a shift count, salary rate or pay type starts from must be between January 2020 and a year ahead (2999 and 1900 used to be stored).
- **Clients, fundings:** a failed database lookup (checking a duplicate client name, or that a funder, borrower or loan exists) now answers 500 instead of reading as "name is free" / "no longer exists"; the "Owes money" filter is done in the database so a large client list can no longer be cut short; a seating capacity or quantity must be a real number (`true`, `"60"`, `[5]` are refused); renaming an individual client to a different name is refused with a message (their name comes from their entity) instead of being dropped with a success. New `sql/53` makes client names unique ignoring case in the database (apply by hand).
- **Clients:** an invalid opening balance or opening date now refuses the whole new client instead of creating it with a warning; a client with contacts or vehicle assignments cannot be deleted (the message says what is attached); an inactive client takes no new bills or payments; entries cannot be dated in the future; only one opening balance stands per client; the Edit Client form has an Active switch.
- **Clients:** malformed requests, decimal ids, and the "Owes money" filter no longer break: a malformed body or an id like `1.5` answers 400 instead of 500 on every client, contact, deployment and statement route; the "Owes money" filter now counts and pages only the clients that owe (it used to show short pages and count everyone). Text fields must be text and have limits (location 150, address 500, GST 20, contact name 150, designation 100, notes 500), a client type must be one from the list, flags must be true or false (a string "false" used to turn a client or contact on), a seating capacity above 200 or a quantity above 1000 is refused, names are unique ignoring case, an individual's name can no longer be edited away from their entity, and a second client for the same entity says so instead of "name already exists".
- **Loans, clients, fundings:** a payment or ledger entry's reference and invoice number are limited to 100 characters (the web forms and the Flutter fields stop there), and payment method, reference, notes, description and invoice number must be text; a made-up `status` or `direction` on the fundings list now answers 400 instead of an empty list; adding a client ledger entry with a malformed body or a decimal client id answers 400 instead of 500.
- **Fundings:** a malformed request, a decimal or non-numeric id, a list filter such as `funder_id=abc`, or a funder, borrower or loan that doesn't exist now answers a clear 400 instead of a 500; notes, payment method, reference, description and rate notes must be text (an object used to be saved as "[object Object]"); a reference can be at most 100 characters (the Flutter field stops there too); a rate above the limit says "Rate can be at most 20% per month / 100% per year" instead of "amount". The funding form's "Funder is required" message clears once a funder is chosen. Long unbroken text no longer stretches the entries table or runs off the phone screen, and an error under a tall form scrolls into view.
- **Fundings, clients and salaries:** the New Funding form, Borrow More / Repay / Pay Interest, Change Rate, the client form (opening balance and its "As of" date), Add Bill / Record Payment, the vehicle deployment form, and the salary windows (settle, rate and "From month", trip count, advance and deduction, the quick advance) now use the same date picker, month picker and money/number inputs as Loans. The salaries month field on desktop is a month picker (months after the current one are greyed out). Entry dates default to today in India rather than UTC. "Settle" starts from ₹0 rather than a negative figure when advances exceed the salary. A client's notes length error is now shown (it was set but never displayed).
- **Loans:** choosing a start date no longer leaves a red "required" message on the first EMI date and EMI day it fills in.
- **Loans:** the New/Edit Loan form, the Record Payment dialog and the EMI calendar's month field now use the library's date picker, month picker and money/number inputs instead of the browser's own date, month and number fields (the same on every browser; amounts can't take an exponent, a minus sign or a third decimal). "Paid On" now defaults to today in India rather than UTC, and can't be a future date. A loan starting on the 31st no longer suggests a first EMI two or three days into the month after next (31 Jan → 3 Mar); it suggests the last day of the next month (28 Feb).

- **UI:** the shared components now live in `src/ui` as an in-house library (styled-components, a folder per component), with 14 new ones (date and month pickers, money and number inputs, menu, popover, toast, alert, form field and form grid, checkbox, switch, chip, avatar). Nothing on any screen looks different: all 120 screenshots (phone and desktop, light and dark) match to the pixel. ([0009](decisions/0009-in-house-ui-library.md))
- **Trip bookings:** searching with a comma (e.g. "Ravi, Kumar") no longer fails with a 500, and the search text can no longer add its own conditions to the filter.
- **Fundings:** recording a rate change and adding an entry now apply the same limits as creating a funding (monthly rate ≤ 20%, annual ≤ 100%, amounts ≤ ₹100 crore, at most two decimals); before, a rate change could store what creation refused.
- **Drivers:** editing a driver with a phone, place, licence number or photo link sent as a number now answers 400 instead of silently clearing that field.

- **Drivers:** a stale or malformed id on edit no longer crashes with a 500 (clean 400/404 now); setting active/inactive with a non-boolean value no longer silently does nothing; malformed requests to add or edit a driver answer 400 instead of 500; name/place/licence number now have sane length limits; the photo-link field now requires an `http://`/`https://` URL; searching with only punctuation returns no results instead of every driver; removed a second, non-functional "Add Driver" page at `/admin/drivers/new`. ([0008](decisions/0008-driver-visibility-and-mobile-similar-name.md))
- **Loans:** money amounts have an upper limit and at most two decimals; future-dated and pre-start payments are rejected; closed loans no longer show as overdue; a loan's closing date is recorded; the payment dialog shows its error where you can see it; the list shows "No loans match" with a Clear filters button. ([0005](decisions/0005-closed-loans-are-not-overdue.md))
- **Salaries:** a driver's per-trip pay rate can no longer be read by staff or driver accounts (the pay-type history is admin-only, like every salary read); per-trip drivers can be settled correctly; money amounts and trip counts are range-checked; a future month's trip count is refused; malformed requests and non-integer ids answer 400 instead of 500.
- **Salaries:** a month can only be marked paid once it is over, on the web and in the app — drivers are paid after the month ends, and settling early locked a month whose absences could still change. ([0007](decisions/0007-settle-only-finished-months.md))
- **Clients, Fundings, Trip bookings:** entries dated "today" with no date given now use India time instead of UTC, so one made between midnight and 05:30 IST is no longer dated a day early.
- **Project setup:** `.claude/` rules, agents, skills and hooks; `docs/decisions/` and `docs/features/`. CLAUDE.md is now an index.
